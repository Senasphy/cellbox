# Deferred specification details

This report records what is still missing from the requested build. The goal remains the full project; these omissions do not count as acceptance.

## Core blockers

- Phase 3 still lacks a live hosted-model fix-loop. No OpenAI-compatible model key or local Ollama endpoint was available. On 2026-11-23, the Python SDK unit suite passed (14 tests), the marked integration passed against a live Docker-backed server (1 test), and the SDK tool tests passed (4 tests) using a temporary virtual environment. On 2026-11-25, the TypeScript SDK `vitest` suite (6 tests), ESM/CJS/DTS build, `scripts/docker-walkthrough.sh`, `scripts/recovery-walkthrough.sh`, and all four Python examples (`fix-loop.py`, `hosted-model.py`, `ollama.py`, `eval-runner.py`) in `--fake-model` mode passed locally against Docker. After fixing the native API/runtime output-cap mismatch and restoring OCI image-config environment variables (including PATH), direct Python SDK live checks and the fake-model fix-loop also passed against a temporary native server. CI has not been rerun; run [44623183371](https://github.com/Senasphy/cellbox/actions/runs/44623183371) is historical evidence of the shell failure before the local EOF fix.
- Phase 4 acceptance is met locally in a delegated systemd user scope (`systemd-run --user --scope -p Delegate=yes`), with documented deviations: the native backend provides OCI image pull/flatten, namespace/cgroup session creation, bounded command execution with live capped stdout/stderr chunks and per-exec signals, CPU/memory/PID, optional cgroup I/O stats, cumulative OOM-kill counters in session metrics, OOM-killed and PID-limit exec classification with memory/PID breach audit records, cleanup (with restrictive-mode chmod fallback), root-confined file read/write/list/delete (atomic writes and regular-file read caps), capped tar archive/extract with full-path and symlink-aware prevalidation, interactive PTY streams with resize, and a soft per-session disk quota watcher. The watcher scans allocated bytes in the writable overlay every two seconds, freezes and kills on quota breach or measurement failure, and records the breach with the failed session state in one SQLite transaction. It also polls cgroup OOM/PID counters every two seconds and records/stops a session when either occurs outside an active exec. On 2026-11-25, `TestNativeResourceLimitsEnforced` passed 5 consecutive times (CPU throttling, PID ceiling with `GOMAXPROCS=1` + netpoller init control I/O, and 32 MiB OOM classification), `make test-security` (`test/security`) passed all 17 Section 17 attack matrix probes, file/archive security checks, resource breaches, chaos kill/reconcile/leak checks, and live native terminal reconnect (256 KiB ring, fixed 30s grace period). Remaining deviations: the host's default service cgroup still requires `systemd-run --user --scope -p Delegate=yes` (or the provided systemd units) and statically linked native test binaries; host file operations use `/proc/<init-pid>/root` with `openat2` confinement rather than init-mediated file-operation messages; only one active exec or terminal is permitted per sandbox; the disk watcher has up to a two-second overshoot window; the terminal reconnect grace period is fixed rather than configurable; and native exec timeout escalates SIGTERM to SIGKILL while Docker timeout still terminates its container.
- The Docker backend has no enforced per-session writable-layer disk limit and is not suitable for hostile workloads.
- Phase 5 has an initial HTTP/HTTPS egress path for native and Docker backends: `none`, host/port allowlists, and configured `internet` mode; per-session Unix proxy sockets; loopback forwarder and proxy environment; IDNA host normalization; DNS resolution with all-address private/reserved-range checks; direct dialing to the validated IP with peer verification; a dedicated `egress_log` table with a paginated endpoint; and matching allow/deny audit events. Docker stays on `NetworkMode:none`, mounts only the per-session proxy socket, and injects the statically linked forwarder executable into the container. The dashboard can choose an image and network mode when creating a session, and configure allowlist entries as `host:port`; the Network tab filters records, refreshes recent activity, and pages through older decisions. On 2026-11-22, `CELLBOX_DOCKER_SOCKET=/run/docker.sock make test-integration` passed: the Docker runtime contract passed, and the live egress test proved direct bypass to `1.1.1.1` failed, `example.org:443` was denied with `policy_denied`, and allowlisted `example.com:443` succeeded with `policy_allowed`. Native delegated-scope checks also passed using a statically linked test binary: in-sandbox `wget` to `1.1.1.1` failed, while allowlisted `pip download` from PyPI and `git ls-remote` from GitHub succeeded through the proxy. A cgo-linked native test binary failed because glibc attempted the deliberately denied `clone3`; static linking is required for native checks. The required section 11 test cases are covered by the focused proxy suite and live native/Docker checks. The API egress-log test confirms allow and deny decisions, including their reason codes, are persisted and returned. Phase 5 acceptance is met. An optional bandwidth cap is not implemented; broader production threat-model review remains in Phase 7.
- Phase 6 acceptance is met locally; the measured host differs from the reference machine, and Docker is slower than the native backend as recorded in `docs/BENCHMARKS.md`. Replay paging/order/output, snapshot CRUD/dependency protection, fork inheritance/layer order, native copy behavior, asciicast v2 encoding and ownership-checked export, and dashboard build have focused local checks. Docker advertises TTY exec support; native advertises interactive PTY support but not TTY exec. Exec and terminal launches now merge session environment values with request overrides. The pool asynchronously prefetches configured curated images at startup, refills after cold no-network sessions, atomically claims matching idle sandboxes, applies requested limits, retires entries at ten minutes, retries failed image prefetch/refill with capped exponential backoff and jitter, and exposes readiness and warm/cold latency metrics. It skips network policies other than `none` and snapshot forks; claimed sandboxes retain the pool initializer hostname. After adding a bounded native image reference cache, the live native benchmark measured cold p50 42 ms and warm p50 8.6 ms; the first cold sample still incurred a 1.95 s registry lookup (p95). Docker's live cold and warm p50 were 813 ms and 374 ms. The reference machine was not identified; results and host details are in `docs/BENCHMARKS.md`. On 2026-11-25, `examples/eval-runner.py` passed 3/3 against Docker after fixing its base-session context manager lifetime; a native `python:3.12-slim` pull timed out after 15 minutes over the network. A live native API exercise verified that a fork sees the snapshot file and excludes a file written later by the parent, and that an eight-snapshot chain produces a flattened layer which remains readable in its fork. It also exposed and fixed a zero-limit accounting bug that rejected every nonempty native snapshot. Native snapshot capture freezes the session cgroup and copies the upper tree; flattening copies the merged root, excludes `/dev`, `/proc`, `/sys`, and `/run`, preserves filesystem metadata and xattrs, and reflinks regular files where supported. Docker's focused live runtime contract and snapshot-fork check also passed. A live native replay check also reproduced recorded command output with timestamped start, output, and end events. The TypeScript SDK `vitest` suite (6 tests) and ESM/CJS/DTS build now pass locally.
- Phase 7 hardening, packaging, threat-model validation, and v1.0 definition-of-done evidence remain incomplete. System and user systemd units and `docs/OPERATIONS.md` have been added and their unit syntax was checked with `systemd-analyze verify`. `SECURITY.md` and `docs/THREAT_MODEL.md` describe disclosure, support policy, implemented controls, and residual risks; independent security review and `staticcheck`/`golangci-lint`/`govulncheck` runs remain outstanding. Five Go fuzz targets (`make fuzz`) passed 5-second runs each, and `test/load` passed a 15-second 4-worker native load test (272 cycles, 0 errors, 0 leaked cgroups); the full 1-hour soak test remains unrun. `.goreleaser.yaml`, a checksum-verifying Linux installer, `make release-dry-run`, and an initial `CHANGELOG.md` have been added, but GoReleaser/Syft/Cosign were unavailable so the integrated release path was not run, and a tag-triggered release workflow was added but not exercised. A public AUR package is deferred because the GitHub source repository is private and cannot be fetched by public AUR builders. The Docker image and demo Compose configuration are implemented; `docker compose config`, the Dockerfile build, and a container `version` smoke check passed locally. The full Compose demo service was not started, and demo recording remains outstanding.
- Phase 8 cluster mode is optional and deferred until single-node acceptance is complete.

## Smaller details deferred for now

- Complete visual theming, manual WCAG review, terminal 60 fps measurement, and the remaining specified Files behaviors have not been audited to the specification's full quality bar.
- Some dashboard operations still use direct `fetch` rather than generated typed operations, and live SSE behavior does not yet meet every reconnect/replay detail in the specification.
- The SDKs, tool schemas, MCP server and CLI have implemented core paths, including snapshot/fork and exec stream resume methods; exhaustive compatibility, shell completions, and live service verification remain incomplete. The Go SDK cursor-resume path passes a focused local HTTP server test, and the TypeScript SDK `vitest` suite passes 6/6 locally. Python and TypeScript both reject cross-origin exec stream URLs before sending the bearer key; Python syntax passes and TypeScript `tsc --noEmit` + `vitest` pass (`pytest` is not installed in the system Python outside a temp venv).
- Snapshot/fork methods are now present in the Go, Python and TypeScript SDKs and the MCP/model-tool dispatchers; the CLI also provides snapshot and fork commands. The eval-runner branches from a shared snapshot and passed live against Docker on 2026-11-25.
- Resource breach recording covers output truncation, timeout, cgroup OOM/PID counter deltas observed when an exec completes, and disk quota events from the native periodic watcher. The native watcher reports OOM/PID counter increases observed between execs. Session metrics expose cumulative OOM-kill counters.

## Recently repaired core wiring

`SpawnInit` re-executes the service binary as `cellbox-init`. The existing `cmd/cellbox/native_init.go` hook dispatches that argv[0] to `RunInit`; init installs the default seccomp filter after its mount setup and before reporting ready. Init accepts bounded exec requests, streams capped stdout/stderr chunks over the control socket, accepts per-exec signals, and returns exit status. Each workload runs through the short-lived `cellbox-exec` helper with rlimits, cleared capabilities, no-new-privileges, seccomp, and a close-on-exec error pipe. A native Runtime creates overlay-backed sessions under per-session cgroups, pulls and flattens host-architecture OCI images, and supports command execution, stats, limit updates, kill, and destroy. Root-confined host file operations and capped, prevalidated archive extraction are implemented. Init-mediated file operations remain incomplete. Focused native package checks, vet, and a static Linux amd64 build pass locally. The shared basic contract has also passed against this backend in a delegated user scope; full Phase 4 acceptance remains unproven because the security, resource enforcement, leak/chaos, and benchmark evidence is incomplete.
