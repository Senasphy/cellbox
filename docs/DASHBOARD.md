# Dashboard authentication

The dashboard exchanges an API key for a browser session with `POST /v1/auth/session` and JSON `{"api_key":"cbx_…"}`. The key is verified through the API and kept only in server memory. The browser receives a 12 hour `cellbox_session` cookie marked `HttpOnly`, `SameSite=Strict`, and `Secure` whenever the request uses TLS. The response also includes a random CSRF token and sets a matching `cellbox_csrf` cookie. The UI keeps the CSRF value in tab memory and sends it as `X-CSRF-Token` for POST, PUT, PATCH, and DELETE requests.

`DELETE /v1/auth/session` invalidates the server-side session and expires both cookies. Session cookies stop working after a service restart; the user signs in again with the API key. API clients can continue to use bearer keys directly. The dashboard does not put keys in localStorage or sessionStorage.

The sessions, timeline exec history, admin keys, system/doctor status, and recent limit breaches use TanStack Query with an OpenAPI generated typed client. Session create/destroy, exec start, key create/revoke, file listing, and file reads use generated typed operations with CSRF headers where applicable. Binary uploads and archive downloads retain direct fetch handling. Remaining dashboard requests are still being migrated from fetch. The dashboard provides Overview and Sessions navigation, session create/destroy, streamed command output, and session detail views for Terminal, Timeline, Files, Metrics, Events, Snapshots, and Replay. The Terminal view uses xterm.js with the WebGL renderer when available, authenticated WebSocket reconnect with bounded backoff, retained in-view scrollback, a screen reader output transcript, explicit copy/paste controls, and interactive PTY shells with resize on Docker and native backends. The server retains disconnected PTYs for 30 seconds and replays up to 256 KiB on reconnect; the Docker-backed reconnect flow passed, while native reconnect remains unverified. Timeline lists paginated execs with command, duration bar, exit state, and sampled peak session memory; it filters commands and lazily streams output into a virtualized line viewer. Overview shows active sessions, CPU, memory, and PID capacity gauges, create/error rate sparklines derived from successive Prometheus counter samples, recent output breaches, and asynchronous host doctor checks for admin keys. The Files tab has a lazy paginated directory tree, drag-and-drop upload, tar download, and a dynamically loaded read-only CodeMirror 6 viewer. A keyboard command palette opens with Ctrl+K or ⌘K and supports navigation and common actions. Session loading now shows skeleton rows; API failures display problem codes and suggested fixes. A light/dark theme toggle, visible keyboard focus, and reduced-motion styles are present; automated axe scans for WCAG 2.1 A/AA pass on representative views; manual assistive technology and complete theme coverage remain pending. Session snapshots refresh over authenticated SSE with client-managed exponential reconnect backoff; the table supports filters, labels, age, bulk destroy, and CPU/memory sparklines from five-second bounded-concurrency runtime samples. The Metrics tab streams per-session CPU, memory, PID, and I/O samples into uPlot, with the configured CPU, memory, and PID limits drawn as lines. Admin keys can be listed, created, and revoked; a new secret is shown once. The System view shows runtime capabilities, doctor checks, and Prometheus text metrics. Images lists images referenced by current sessions. Admin image list/pull/remove endpoints exist, while list and removal require the backend's optional image-management capability; native currently supports pull but not cache listing or removal.

The Overview renders recent limit breach records by kind. The service records output, timeout, memory/OOM, and PID breaches; the native runtime also records disk quota breaches from its periodic writable-overlay watcher. Docker does not enforce per-session disk quotas. Native OOM and PID events are detected from cgroup counter deltas when an exec completes, so events outside an exec are not continuously monitored. Phase 3 still lacks complete light/dark theme coverage and manual accessibility review. Peak memory is sampled from session stats every 250 ms while an exec is active and is a session level measurement. The terminal supports Docker and native PTYs with resize, reconnect, a 256 KiB scrollback ring, and a 30-second detached-session grace period. The reconnect flow passed the Docker-backed Playwright test; a separate native reconnect run remains unverified. The grace period is currently fixed. The file viewer currently treats files as text and does not provide syntax-specific language modes. Warm pool capability and idle counts are exposed in the System view and Prometheus metrics when configured, but claim/refill latency has not been benchmarked. The admin-only System view exposes effective service configuration and masks the TLS private key path. The session Network view filters native egress decisions, refreshes the latest records, and pages through older decisions. Snapshot controls create, inspect, fork, and delete filesystem snapshots; the Replay view renders recorded output in xterm with playback speed and a position scrubber, and links TTY execs to their asciicast v2 download. Live native fork isolation and the complete security review remain pending.
