# Dashboard authentication

The dashboard exchanges an API key for a browser session with `POST /v1/auth/session` and JSON `{"api_key":"cbx_…"}`. The key is verified through the API and kept only in server memory. The browser receives a 12 hour `cellbox_session` cookie marked `HttpOnly`, `SameSite=Strict`, and `Secure` whenever the request uses TLS. The response also includes a random CSRF token and sets a matching `cellbox_csrf` cookie. The UI keeps the CSRF value in tab memory and sends it as `X-CSRF-Token` for POST, PUT, PATCH, and DELETE requests.

`DELETE /v1/auth/session` invalidates the server-side session and expires both cookies. Session cookies stop working after a service restart; the user signs in again with the API key. API clients can continue to use bearer keys directly. The dashboard does not put keys in localStorage or sessionStorage.

The dashboard provides Overview and Sessions navigation, session create/destroy, streamed command output, file upload/download, and session detail views for Terminal, Timeline, Files, Metrics, and Events. A keyboard command palette opens with Ctrl+K or ⌘K and supports navigation and common actions. Session snapshots refresh over an authenticated SSE connection with browser-managed reconnect backoff; the table supports filters, labels, age, and bulk destroy. The Metrics tab streams per-session CPU, memory, PID, and I/O samples into uPlot, with the configured CPU, memory, and PID limits drawn as lines. Admin keys can be listed, created, and revoked; a new secret is shown once. The System view shows runtime capabilities and Prometheus text metrics. Images lists images referenced by current sessions; the API does not yet expose image management.

Phase 3 still lacks overview capacity gauges and sparklines, CPU and memory sparklines in the session table, an xterm.js terminal, a full lazy file tree and code viewer, a virtualized timeline/output viewer, complete light/dark theme support, and an accessibility audit. Effective configuration is not exposed by the current API. Network, snapshot, and replay views depend on later phases.
