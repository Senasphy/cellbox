# Build progress

## Phase 0: Foundations — complete (local acceptance passed)

Implemented: Go module, CLI skeleton (`version`, `doctor`, `serve`), strict config loading with environment overrides, slog redaction, SQLite WAL store and forward-only migration runner, problem+json type, prefixed sortable IDs, OpenAPI skeleton, Makefile, CI workflow, Apache-2.0 license.

Acceptance status: `version`, `doctor`, strict config tests, redaction tests, migration idempotency on an empty database, `go test -race ./...`, `go vet ./...`, and a CGO-disabled build passed locally on Linux/amd64. The checked-in CI workflow has not been run remotely yet.

Known gaps: doctor does not yet verify kernel version, cgroup delegation, user namespaces, overlayfs, seccomp, or devpts. The checked-in CI workflow has not run remotely.

## Phase 1: Docker backend and core API — in progress

Implemented: backend-neutral Runtime/Sandbox interfaces; Docker Engine Unix-socket client; local image inspection and pull; container create/start/destroy with memory, swap, CPU, PID, no-network, dropped-capability and no-new-privileges settings; command exec stream decoding and exit status; file and archive transfer primitives with path/tar checks; snapshot, limit update, stats and kill calls. Docker now reports that per-container disk quotas are unsupported and rejects explicit requests, avoiding unsupported `StorageOpt` settings on common daemons. The shared runtime conformance suite exercises image resolution, create/destroy, exec, file and archive operations, limit updates, stats, kill, and unsupported TTY behavior; Docker also has a focused snapshot adapter test. API key generation, SHA-256-only persistence, revocation, and CLI key commands are implemented. The `cellbox run` CLI command creates a no-network session, streams command output, preserves exit codes and signal status, and destroys the session on completion. The HTTP server exposes health/readiness and authenticated system, session lifecycle, exec wait/SSE, file, and archive routes. Session and exec state/output are persisted; API keys are scope checked; the service creates and prints the first admin key once, refuses non-loopback binds without `--allow-remote`, and supports TLS config.

Validation so far: unit tests cover image metadata, container isolation settings and CPU/PID create settings, Docker limit-update mapping and stats decoding, exec stdout/stderr and exit status, TTY final-byte handling, bounded timeout cleanup, file/archive transfer, snapshot commit, path traversal rejection, unsupported disk quota reporting, and invalid limits. The expanded shared runtime suite passes through the Docker runtime adapter against a stateful Docker Engine stub. The live-daemon contract is an explicit `make test-integration` target and a required CI step after `docker info`; CI also runs `scripts/docker-walkthrough.sh` against the live service. CI has not yet run remotely. A temporary rootless Docker 29.9 daemon started successfully from `/tmp`, but the live contract and a plain `docker run` both failed at OCI container startup with `can't copy bootstrap data to pipe: write init-p: broken pipe`; this host's outer sandbox prevents running containers, even under the temporary daemon. That daemon and its temporary files were stopped and removed. API tests cover all documented Phase 1 route variants, including wait and streaming execs, file and archive transfers, ownership, invalid requests, and OpenAPI request/response validation. SSE and tar payloads receive explicit checks because the OpenAPI validator cannot decode those media types. The latest `go test -race ./...` run passed. Earlier local checks also passed for `go vet ./...`, a CGO-disabled build, shell syntax for the walkthrough, and the workflow YAML parse. A local smoke run confirmed `/healthz` returns 200, `/v1/system` returns 401 without a key, and returns 200 with a generated admin key.

Acceptance status: not met. The shared suite passes against the Docker adapter stub, but neither the required live Docker daemon run nor the live service curl walkthrough has passed; local container startup is blocked by the host's outer sandbox. The CI workflow now requires both checks, but no remote CI result is available. Docker has no writable-layer size cap, interactive terminals are not implemented, and the full security/limit contract is unproven. API pagination and idempotency remain incomplete. Do not use this backend for untrusted workloads yet.
