# Build progress

## Phase 0: Foundations — complete (local acceptance passed)

Implemented: Go module, CLI skeleton (`version`, `doctor`, `serve`), strict config loading with environment overrides, slog redaction, SQLite WAL store and forward-only migration runner, problem+json type, prefixed sortable IDs, OpenAPI skeleton, Makefile, CI workflow, Apache-2.0 license.

Acceptance status: passed. `version`, `doctor`, strict config tests, redaction tests, migration idempotency on an empty database, `go test -race ./...`, `go vet ./...`, and CGO-disabled builds passed locally and in GitHub Actions on Linux/amd64 and arm64.

Known gaps: doctor does not yet verify kernel version, cgroup delegation, user namespaces, overlayfs, seccomp, or devpts.

## Phase 1: Docker backend and core API — complete

Implemented: backend-neutral Runtime/Sandbox interfaces; Docker Engine Unix-socket client; local image inspection and pull; container create/start/destroy with memory, swap, CPU, PID, no-network, dropped-capability and no-new-privileges settings; command exec stream decoding and exit status; file and archive transfer primitives with path/tar checks; snapshot, limit update, stats and kill calls. Docker now reports that per-container disk quotas are unsupported and rejects explicit requests, avoiding unsupported `StorageOpt` settings on common daemons. The shared runtime conformance suite exercises image resolution, create/destroy, exec, file and archive operations, limit updates, stats, kill, and unsupported TTY behavior; Docker also has a focused snapshot adapter test. API key generation, SHA-256-only persistence, revocation, local CLI commands, and admin-scoped HTTP create/list/revoke routes are implemented. HTTP list responses exclude secret material, and creation returns a secret only once. Session, exec, and directory listings use bounded cursor pagination. The Docker adapter caps directory listing results at 100,000 entries. The HTTP API routes signals to active exec handles and returns a coded unsupported response for Docker, which cannot signal an individual exec. The `cellbox run` CLI command creates a no-network session, streams command output, preserves exit codes and signal status, and destroys the session on completion. The HTTP server exposes health/readiness and authenticated system, session lifecycle, exec wait/SSE/signal, file, archive, and API key routes. Session and exec state/output are persisted; API keys are scope checked; the service creates and prints the first admin key once, refuses non-loopback binds without `--allow-remote`, and supports TLS config.

Validation so far: unit tests cover image metadata, container isolation settings and CPU/PID create settings, Docker limit-update mapping and stats decoding, exec stdout/stderr and exit status, output caps, TTY final-byte handling, bounded timeout cleanup, idempotent kill after a stopped container, file/archive transfer, snapshot commit, path traversal rejection, unsupported disk quota reporting, and invalid limits. The shared runtime contract checks separate stdout/stderr, output caps, archive round trips, rejects relative and absolute path traversal, verifies timeout cleanup, and verifies a killed sandbox rejects new execs; the Docker adapter passes it against a stateful Engine stub. Archive extraction now validates and sanitizes into a private temporary file before making any Docker API request, so a later malicious archive entry cannot leave earlier files written. API tests cover key creation, scope enforcement, one-time secret exposure, listing without secret material, revocation, cursor pagination for sessions, execs, and directory entries, signal forwarding and the unsupported Docker response, all documented Phase 1 route variants, wait and streaming execs, file and archive transfers, ownership, invalid requests, and OpenAPI request/response validation. API file and working-directory path checks reject absolute as well as relative traversal. SSE and tar payloads receive explicit checks because the OpenAPI validator cannot decode those media types. The live-daemon contract is an explicit `make test-integration` target and a required CI step after `docker info`; CI also runs `scripts/docker-walkthrough.sh` against the live service. GitHub Actions run [39290863689](https://github.com/Senasphy/cellbox/actions/runs/39290863689) passed on 2026-10-19: CI passed on Linux/amd64 and Linux/arm64, including the live Docker contract and `scripts/docker-walkthrough.sh`. Local validation also passed `go test -race ./...`, `go vet ./...`, a CGO-disabled build, shell syntax for the walkthrough, and the workflow YAML parse. A local smoke run confirmed `/healthz` returns 200, `/v1/system` returns 401 without a key, and returns 200 with a generated admin key. The local Docker daemon experiment could not start containers because this host's outer sandbox blocked OCI startup; the hosted CI run clears that runtime gate.

Acceptance status: met. The shared runtime contract, API contract tests, live Docker contract, and documented HTTP walkthrough passed. Known gaps carried forward: Docker has no writable-layer size cap, interactive terminals are not implemented, and the full security/limit contract is unproven. These constraints remain documented; do not use this backend for untrusted workloads yet.

## Phase 2: Reliability layer — in progress

Implemented before this phase: session and exec state/output persistence, bounded SSE replay from `Last-Event-ID`, and basic TTL fields on session records. Implemented in this phase so far: persisted 24-hour idempotency response replay for successful POST requests, with per-authenticated-key request namespaces, body mismatch detection, and a test proving retries do not create a second session; startup recovery removes labeled orphan Docker containers and marks formerly active sessions `lost`; a five-second background reaper expires sessions by wall-clock or idle TTL and retries cleanup from `stopping`; session keys receive default session, memory, and rolling request-rate quotas; session creation rejects quota or host/cgroup capacity overcommit with coded errors and `Retry-After`; SQLite serializes and validates legal session state transitions transactionally; session and exec state changes are audited in the same transactions, with a paginated owner-scoped events endpoint; `/metrics` exports session, capacity, exec, creation-duration, and output-byte metrics. Tests cover idempotent replay, quota/rate rejection, capacity rejection, startup recovery, randomized state transition sequences, TTL expiration, metrics exposition, collector drain, and atomic lifecycle audit events. CI now includes `scripts/recovery-walkthrough.sh`, which kills the service during a long exec and checks that restart leaves the session lost and removes its Docker container; its first hosted run is pending. Remaining work includes per-session actor goroutines, broader goroutine-leak acceptance tests, audit retention, full HTTP/runtime metrics, and verification of SSE resume behavior. No Phase 2 acceptance criteria have passed yet.
