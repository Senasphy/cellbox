# Build progress

## Phase 0: Foundations — complete (local acceptance passed)

Implemented: Go module, CLI skeleton (`version`, `doctor`, `serve`), strict config loading with environment overrides, slog redaction, SQLite WAL store and forward-only migration runner, problem+json type, prefixed sortable IDs, OpenAPI skeleton, Makefile, CI workflow, Apache-2.0 license.

Acceptance status: passed. `version`, `doctor`, strict config tests, redaction tests, migration idempotency on an empty database, `go test -race ./...`, `go vet ./...`, and CGO-disabled builds passed locally and in GitHub Actions on Linux/amd64 and arm64.

Known gaps: doctor does not yet verify kernel version, cgroup delegation, user namespaces, overlayfs, seccomp, or devpts.

## Phase 1: Docker backend and core API — complete

Implemented: backend-neutral Runtime/Sandbox interfaces; Docker Engine Unix-socket client; local image inspection and pull; container create/start/destroy with memory, swap, CPU, PID, no-network, dropped-capability and no-new-privileges settings; command exec stream decoding and exit status; file and archive transfer primitives with path/tar checks; snapshot, limit update, stats and kill calls. Docker now reports that per-container disk quotas are unsupported and rejects explicit requests, avoiding unsupported `StorageOpt` settings on common daemons. The shared runtime conformance suite exercises image resolution, create/destroy, exec, file and archive operations, limit updates, stats, kill, and unsupported TTY behavior; Docker also has a focused snapshot adapter test. API key generation, SHA-256-only persistence, revocation, local CLI commands, and admin-scoped HTTP create/list/revoke routes are implemented. HTTP list responses exclude secret material, and creation returns a secret only once. Session, exec, and directory listings use bounded cursor pagination. The Docker adapter caps directory listing results at 100,000 entries. The HTTP API routes signals to active exec handles and returns a coded unsupported response for Docker, which cannot signal an individual exec. The `cellbox run` CLI command creates a no-network session, streams command output, preserves exit codes and signal status, and destroys the session on completion. The HTTP server exposes health/readiness and authenticated system, session lifecycle, exec wait/SSE/signal, file, archive, and API key routes. Session and exec state/output are persisted; API keys are scope checked; the service creates and prints the first admin key once, refuses non-loopback binds without `--allow-remote`, and supports TLS config.

Validation so far: unit tests cover image metadata, container isolation settings and CPU/PID create settings, Docker limit-update mapping and stats decoding, exec stdout/stderr and exit status, output caps, TTY final-byte handling, bounded timeout cleanup, idempotent kill after a stopped container, file/archive transfer, snapshot commit, path traversal rejection, unsupported disk quota reporting, and invalid limits. The shared runtime contract checks separate stdout/stderr, output caps, archive round trips, rejects relative and absolute path traversal, verifies timeout cleanup, and verifies a killed sandbox rejects new execs; the Docker adapter passes it against a stateful Engine stub. Archive extraction now validates and sanitizes into a private temporary file before making any Docker API request, so a later malicious archive entry cannot leave earlier files written. API tests cover key creation, scope enforcement, one-time secret exposure, listing without secret material, revocation, cursor pagination for sessions, execs, and directory entries, signal forwarding and the unsupported Docker response, all documented Phase 1 route variants, wait and streaming execs, file and archive transfers, ownership, invalid requests, and OpenAPI request/response validation. API file and working-directory path checks reject absolute as well as relative traversal. SSE and tar payloads receive explicit checks because the OpenAPI validator cannot decode those media types. The live-daemon contract is an explicit `make test-integration` target and a required CI step after `docker info`; CI also runs `scripts/docker-walkthrough.sh` against the live service. GitHub Actions run [39290863689](https://github.com/Senasphy/cellbox/actions/runs/39290863689) passed on 2026-10-19: CI passed on Linux/amd64 and Linux/arm64, including the live Docker contract and `scripts/docker-walkthrough.sh`. Local validation also passed `go test -race ./...`, `go vet ./...`, a CGO-disabled build, shell syntax for the walkthrough, and the workflow YAML parse. A local smoke run confirmed `/healthz` returns 200, `/v1/system` returns 401 without a key, and returns 200 with a generated admin key. The local Docker daemon experiment could not start containers because this host's outer sandbox blocked OCI startup; the hosted CI run clears that runtime gate.

Acceptance status: met. The shared runtime contract, API contract tests, live Docker contract, and documented HTTP walkthrough passed. Known gaps carried forward: Docker has no writable-layer size cap, interactive terminals are not implemented, and the full security/limit contract is unproven. These constraints remain documented; do not use this backend for untrusted workloads yet.

## Phase 2: Reliability layer — complete

Implemented before this phase: session and exec state/output persistence, bounded SSE replay from `Last-Event-ID`, and basic TTL fields on session records. Implemented in this phase: persisted 24-hour idempotency response replay for successful POST requests, with per-authenticated-key request namespaces, body mismatch detection, revoked-key revalidation, and a test proving retries do not create a second session; startup recovery removes labeled orphan Docker containers and marks formerly active sessions `lost`; a five-second background reaper expires sessions by wall-clock or idle TTL and retries cleanup from `stopping`; session keys receive default session, memory, and rolling request-rate quotas; session creation rejects quota or host/cgroup capacity overcommit with coded errors and `Retry-After`; SQLite serializes and validates legal session state transitions transactionally; session and exec state changes are audited in the same transactions, with a paginated owner-scoped events endpoint; retention sweeps prune exec output and audit events per configured days; `/metrics` exports session, capacity, exec, creation-duration, and output-byte metrics. Tests cover idempotent replay, quota/rate rejection, capacity rejection, startup recovery, randomized state transition sequences, TTL expiration, metrics exposition, collector drain, retention pruning, and atomic lifecycle audit events. GitHub Actions run [39295095345](https://github.com/Senasphy/cellbox/actions/runs/39295095345) passed on 2026-10-19 on Linux/amd64 and Linux/arm64, including the Docker contract, curl walkthrough, and `scripts/recovery-walkthrough.sh` crash/restart check. Acceptance status: met. The specified per-session actor goroutines were replaced with serialized SQLite state transactions (see `docs/DECISIONS.md`); HTTP request metrics and some runtime-specific metrics remain incomplete.

## Phase 3: Agent-facing surface and dashboard — in progress

Implemented locally: a typed Python package with sync and async `httpx` clients, context-managed session cleanup, SSE output iteration, idempotent transport retry, and typed problem exceptions; a fetch-based TypeScript client with ESM/CJS build metadata and `AsyncIterable` SSE output; and a small Go client. Model tool schemas are provided in OpenAI and Anthropic formats, with Python dispatch helpers that independently cap stdout and stderr at 16 KiB while retaining head and tail plus an omitted-byte marker. The `cellbox mcp` command provides stdio and streamable-HTTP transports, lazily creates a conservative no-network session, exposes run/file/list/reset tools, and returns clear unsupported errors for snapshot and fork because those API routes are Phase 6 work. The command result format always includes exit code, duration, timeout/OOM reason, and bounded output.

The examples directory now includes hosted-model, Ollama, deterministic fake-model fix-loop, and concurrent eval-runner examples. A Next.js 15 static export has been embedded through `go:embed`; its dashboard exchanges an API key for a 12-hour HttpOnly, SameSite=Strict session cookie, checks CSRF tokens on writes, creates and destroys sessions, runs streamed commands, uploads/downloads files, and displays text metrics. The key is not stored in browser storage. CI builds both SDK/dashboard packages, runs Python SDK tests, includes the Python SDK and fake-model loop in the live Docker walkthrough, and provisions Playwright for browser acceptance.

Local validation before the cookie-auth addition passed `go test -race ./...`, `go vet ./...`, a CGO-disabled build, MCP protocol client coverage, embedded dashboard handler coverage, Python SDK/tool tests (7 passed; one live integration test deselected), TypeScript type checking, static Next.js export, and shell syntax. Cookie login, cookie flags, CSRF rejection, authenticated forwarding, and embedded script serving pass local Go tests. GitHub Actions runs [39385121376](https://github.com/Senasphy/cellbox/actions/runs/39385121376) and [39386728377](https://github.com/Senasphy/cellbox/actions/runs/39386728377) passed on 2026-10-20. They cover the Python SDK, TypeScript build, amd64/arm64 Go matrix, live Docker contract, full walkthrough, browser flow, session detail navigation, temporary key creation and revocation, and recovery walkthrough. The dashboard includes basic Terminal, Timeline, Files, Metrics, and Events session detail views plus Images inventory, Keys management, and System capability/metrics pages; the API has no image-management or effective-configuration endpoints. Phase 3 remains in progress because SSE table refresh, charts and sparklines, xterm.js, keyboard navigation, accessibility audit, and several specified file-browser details remain incomplete. Snapshot/fork, network, replay, and eval fork-start behavior are later-phase gaps.

## Phase 4: Native runtime — in progress

The six required spikes are recorded in `docs/DECISIONS.md`. On this Arch Linux host (kernel 7.2.11), unprivileged user/mount namespaces, rootless overlayfs with `userxattr`, and a private devpts `newinstance` mount work. A `SOCK_SEQPACKET` descriptor-passing smoke test passed. The Go 1.23 API exposes `SysProcAttr.UseCgroupFD` and `CgroupFD`, but this process's writable service cgroup exposes only memory and pids, not cpu, so the actual `CLONE_INTO_CGROUP` experiment is not yet validated. The Ubuntu AppArmor sysctl is absent on this host. The seccomp dependency is integrated; a subprocess test installs the TSYNC filter and confirms a denied ptrace call returns `EPERM`.

Implemented so far: `cellbox doctor` checks kernel minimum, cgroup-v2 controllers at the service cgroup, writable child-cgroup delegation, user namespaces, optional AppArmor restriction, actual rootless overlay and devpts mounts, seccomp availability, a 1 GiB free-space threshold, and informational `/dev/kvm` presence. The native package has a delegated cgroup hierarchy initializer, per-session cgroup-v2 limit/stats/kill/cleanup helpers, a bounded JSON `SOCK_SEQPACKET` control protocol that transfers descriptors with `SCM_RIGHTS`, a namespace init mount setup, a host-side namespace spawn path with single-id maps and cgroup placement, and a default-allow seccomp profile with TSYNC and EPERM deny rules; component tests cover these pieces. The seccomp filter is not yet installed in an exec helper, and no native `Runtime` backend, workload supervisor, enforcement monitoring, or full security suite exists; Phase 4 acceptance is pending.
