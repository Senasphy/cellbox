# Introduction

**CellBox** is a self-hostable single-binary Go service that provisions isolated, disposable Linux sandboxes for AI agents, evaluation harnesses, and code-execution workflows.

A client (an agent, SDK, CLI, or MCP host) creates a **session** with an [OCI image](https://opencontainers.org/about/overview/), resource limits, and a network policy. Inside that session, the client runs commands with resumable output streaming, reads and writes files, attaches interactive PTY terminals, captures immutable filesystem snapshots, and forks parallel child sessions.

<Callout type="info" title="Agent Loop Boundary">
The language model, prompt orchestration, and model API keys stay **outside** CellBox. CellBox never holds LLM credentials and never calls a model API. It is a pure execution primitive.
</Callout>

## Architecture

<ArchitectureFlowFigure />

Every native sandbox is launched by re-executing the `cellbox` binary itself inside new [Linux namespaces](https://man7.org/linux/man-pages/man7/namespaces.7.html) and directly inside its own [cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) (`CLONE_INTO_CGROUP`). The parent supervisor communicates with `cellbox-init` over a private `SOCK_SEQPACKET` Unix socket using `SCM_RIGHTS` descriptor passing. If the service exits, `PR_SET_PDEATHSIG` tears down child sandboxes, and startup reconciliation cleans up any orphaned cgroups and marks leftover sessions as `lost`.

## Choosing a Backend: `native` vs `docker`

CellBox provides two runtime backends configured via `backend: native` (default) or `backend: docker`:

| Capability | `native` (Default) | `docker` (Bootstrap / Compatibility) |
| --- | --- | --- |
| **Daemon Dependency** | None (rootless Linux syscalls) | Requires reachable Docker Engine socket |
| **Root Requirement** | Unprivileged user (`user` namespaces) | Daemon-managed (Docker socket = host root) |
| **Filesystem Isolation** | Rootless `overlayfs` (`userxattr`) + `pivot_root` | Docker container rootfs |
| **File API Mediation** | `cellbox-init` + `openat2` confinement | Docker Engine archive/exec APIs |
| **CPU / Memory / PIDs** | Delegated cgroup v2 (`cpu`, `memory`, `pids`) | Daemon-managed container cgroups |
| **Writable Disk Cap** | Soft cap (2s overlay scan watcher) | Unsupported (`disk_limits: false`) |
| **Network Egress Policy** | `none`, `allowlist` (proxy), `internet` (opt-in) | `none` only (`NetworkMode=none`) |
| **Interactive PTY (`/terminal`)** | Yes (grace period + 256 KiB scrollback) | Yes (grace period + 256 KiB scrollback) |
| **TTY Exec (`tty: true`)** | Yes + asciicast v2 export | Yes + asciicast v2 export |
| **Signal Active Exec** | Yes (`POST .../execs/{id}/signal`) | Unsupported (`capability_unsupported`) |
| **Snapshots & Forking** | `cgroup.freeze` + overlay layer copy (auto-flatten at depth 7) | Docker image commits |
| **Image Management (`GET/DELETE /v1/images`)** | Pull supported; list/remove unimplemented | Full list, pull, and remove |

<Callout type="warn" title="Security Boundary">
The native backend isolates workloads using Linux user, mount, PID, network, IPC, UTS, and cgroup namespaces, cgroup v2 resource limits, a [seccomp filter](https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html), and capability dropping. It shares the host kernel, so a kernel vulnerability can allow escape. For hostile multi-tenant workloads, run CellBox inside a dedicated virtual machine. Never expose the service to untrusted networks without TLS and the quotas and egress policy described in this documentation.
</Callout>
